# سامانه مدیریت فرایندهای کسب‌وکار (BPMS)

پیاده‌سازی مبتنی بر **سند جامع نیازمندی‌ها نسخه ۲.۰** — سامانه تحت‌وب BPMS با پشتیبانی کامل فارسی و راست‌به‌چپ.

## پشته فناوری (مطابق تصمیم‌های قطعی سند §۳)

| لایه | فناوری |
|------|--------|
| API | FastAPI (Python 3.12) |
| ORM / Migration | SQLAlchemy 2.x + Alembic |
| قرارداد API | Pydantic v2 |
| موتور اجرای BPMN | **SpiffWorkflow 3.2** (انتخاب‌شده پس از نمونه فنی فاز صفر) |
| فرانت‌اند | React 18 + TypeScript + Vite |
| رابط و RTL | Ant Design 5 با `direction="rtl"` + فونت وزیرمتن |
| طراح BPMN | bpmn-js 17 |
| Drag & Drop فرم | dnd-kit |
| داده پایگاه | SQLite (توسعه/پایلوت) → PostgreSQL (عملیات — فقط با تغییر `BPMS_DATABASE_URL`) |
| Worker / صف | **Celery + Redis** (عملیات) یا زمان‌بند درون‌فرایندی (توسعه — `BPMS_SCHEDULER_MODE`) |
| رویداد زنده | **SSE** با پل اختیاری Redis برای استقرار چندفرایندی |
| تست بک‌اند / رابط | pytest (۹۰ آزمون) / Vitest (۸ آزمون مشترک) |

## اجرای سریع

```bash
# بک‌اند
cd backend
python3 -m venv .venv && source .venv/bin/activate    # اختیاری
pip install -r requirements.txt
alembic upgrade head            # ساخت جداول
python -m app.seed              # داده نمونه: کاربران، فرم‌ها، فرایند «درخواست خرید»
uvicorn app.main:app --port 8000 --reload

# فرانت‌اند (توسعه)
cd ../frontend
npm install
npm run dev                     # http://localhost:3000 (پروکسی API به 8000)

# تولید (سرو توسط FastAPI)
npm run build                   # خروجی در frontend/dist و به‌صورت خودکار توسط بک‌اند سرو می‌شود
```

## قابلیت‌های پیاده‌سازی‌شده

### بخش اول — طراحی و اجرای فرایند
- طراح BPMN تحت‌وب با bpmn-js: باز کردن/ذخیره `.bpmn`، خروجی SVG، انتخاب عنصر و تنظیمات، **اعتبارسنجی پیش از انتشار با تفکیک خطا/هشدار** (AC-02)
- موتور اجرا SpiffWorkflow: شروع با فرم، وظیفه انسانی، دروازه انحصاری با شرط، انشعاب/اتصال موازی، زیرفرایند (Call Activity)، تایمر، فعالیت سیستمی (ServiceTask) با کانکتور، حالت خطا + **Incident قابل رسیدگی با تلاش مجدد** (AC-15)
- **بازیابی وضعیت پس از ری‌استارت** از طریق serialize/deserialize (AC-13)
- نسخه‌بندی: هر نمونه به نسخه ثابت متصل می‌ماند؛ انتشار نسخه جدید نمونه‌های جاری را تغییر نمی‌دهد (AC-14)

### بخش دوم — فرم‌ساز و داده
- سه جزء مستقل: Form Designer / Form Schema (JSON نسخه‌بندی‌شده) / Form Renderer
- انواع فیلد: متنی، عددی، مبلغ (واحد پول صریح)، تاریخ **جلالی**، **کد ملی** (رقم کنترل + حفظ صفر ابتدایی)، **موبایل** (`^09[0-9]{9}$` پس از یکسان‌سازی ارقام فارسی/عربی) (AC-04/05/06)
- اعتبارسنجی دو سطحی: مرورگر برای بازخورد سریع + **سرور به‌عنوان مرجع نهایی** با موتور مشترک قواعد
- زیرفرم تکرارشونده و تک‌نمونه‌ای با حداقل/حداکثر ردیف و اعتبارسنجی ردیف (AC-08)
- فرمول‌ساز **امن بدون eval** (Parser اختصاصی: `SUM(items.qty)`، `IF`، `ROUND`، مقایسه‌ها) — قرینه سمت مرورگر و سرور با **مجموعه آزمون مشترک**
- جداول پایه (Lookup) سلسله‌مراتبی با اتصال به کنترل‌ها و بررسی گزینه در سرور (AC-07)

### بخش سوم — قوانین، فعالیت‌ها و یکپارچه‌سازی
- شرط‌های مسیر به‌صورت عبارت محدود روی متغیرهای فرایند (`action == 'approve'`)
- کانکتورهای `mock:*` و `http:METHOD:URL` با timeout و retry محدود و ثبت خطا
- محیط اسکریپت محدودشده (بدون import/open آزاد) — منع اجرای آزاد کد کاربران

### بخش چهارم — کارتابل، مشاهده و گزارش
- کارتابل: وظایف من، **صف گروهی با Claim و کنترل رقابت** (جلوگیری از دریافت هم‌زمان — AC-12)، انجام‌شده‌ها، فیلتر و جست‌وجو
- واگذاری/آزادسازی وظیفه، جانشینی در بازه زمانی
- **نمودار زنده** با نشانگر فعالیت‌های فعال/تکمیل‌شده/خطادار روی نسخه واقعی نمونه
- تاریخچه کامل رویدادها + اعلان داخل سامانه + ممیزی فقط‌مشاهده

### بخش پنجم و ششم — معماری، امنیت، کیفیت
- احراز هویت JWT + bcrypt، کنترل دسترسی نقش‌محور با مجوز صریح، محدودیت سطح API
- قالب خطای یکسان + شناسه پیگیری، OpenAPI در `/docs`
- SQLite با `foreign_keys` و WAL؛ مایگریشن Alembic با `render_as_batch` (سازگاری PostgreSQL)
- ثبت ممیزی عملیات حساس، پوشاندن داده حساس در لاگ کانکتورها

### فاز ۳ — قابلیت‌های حرفه‌ای
- **جدول تصمیم (DMN سبک)**: ورودی/خروجی/قواعد با سیاست‌های FIRST/UNIQUE/ANY/PRIORITY/COLLECT؛ ارزیاب امن بدون eval؛ اتصال به وظیفه (`decisionKey`) یا کانکتور `dmn:key`؛ اعتبارسنجی ارجاع‌ها در انتشار؛ ویرایشگر گرید + آزمون ارزیابی در UI
- **تقویم کاری**: برنامه هفتگی هفته ایرانی (شنبه تا جمعه) با وقفه‌ها، تعطیلی یک‌باره/سالانه با انتخاب جلالی؛ محاسبه مهلت وظایف بر پایه ساعات اداری (`config_json.calendarId`)؛ پیش‌نمایش مهلت
- **Worker پایدار (Celery)**: beat برای تیک تایمرها (۳۰ ثانیه) و پایش SLA (۵ دقیقه) — هشدار ۸۰٪ و فرازدگی مهلت با اعلام یک‌باره؛ حالت درون‌فرایندی برای توسعه/پایلوت بدون Redis
- **SSE**: جریان `/events/stream` به تفکیک کاربر با انتشار پس از commit؛ toast و تازه‌سازی خودکار کارتابل/نمونه/اعلان‌ها؛ پل Redis اختیاری برای چندفرایندی

## سناریوی نمونه سند §۳۵ (درخواست خرید)

با داده اولیه آماده است: ثبت درخواست (فرم با کد ملی/موبایل/تاریخ شمسی/اقلام) → تأیید مدیر (صف گروهی نقش مدیر) → انشعاب موازی (سرویس ثبت سفارش + اطلاع‌رسانی مالی) → خاتمه. مسیرهای «رد» و «بازگشت برای اصلاح» نیز فعال‌اند.

آزمون خودکار همین سناریو از طریق HTTP: `python3 scripts/e2e_api_test.py` (سرور باید روشن باشد).

## ساختار مخزن

```
backend/
  app/
    core/            # تنظیمات، دیتابیس، امنیت، مجوز
    modules/
      identity/      # کاربر، نقش، مجوز
      organization/  # واحد سازمانی، جانشینی
      lookups/       # جداول پایه
      forms/         # فرم‌ساز: مدل، اعتبارسنجی، ابزارهای ایرانی، فرمول امن
      processes/     # تعریف/نسخه/اعتبارسنجی/انتشار فرایند
      engine/        # آداپتور SpiffWorkflow، کانکتورها (mock/http/dmn)، سرویس اجرا
      decisions/     # فاز ۳: جدول تصمیم (DMN سبک) — مدل، ارزیاب امن، API
      calendars/     # فاز ۳: تقویم کاری — مدل، محاسبه ساعات اداری، API
      events/        # فاز ۳: گذرگاه رویداد زنده (SSE) + انتشار پس از commit
      worker/        # فاز ۳: Celery (تیک + SLA) و زمان‌بند درون‌فرایندی
      tasks/         # کارتابل (inbox/group/claim/complete)
      audit/ attachments/ notifications/
  alembic/           # مایگریشن نسخه‌بندی‌شده
  data/bpmn/         # فرایند نمونه «درخواست خرید»
  tests/             # ۹۰ آزمون pytest
frontend/
  src/
    lib/             # persian.ts، formula.ts، liveEvents.ts (SSE) + آزمون مشترک
    components/      # FormRenderer، FormDesigner، BpmnViewer، JalaliDatePicker
    pages/           # داشبورد، کارتابل، درخواست‌ها، فرم‌ساز، طراح BPMN، پایش، مدیریت، جدول‌های تصمیم، تقویم کاری
docs/               # معماری، ماتریس انطباق BPMN، استقرار، محدودیت‌ها، فاز ۳
```

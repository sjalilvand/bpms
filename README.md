# سامانه مدیریت فرایندهای کسب‌وکار (BPMS)

پیاده‌سازی مبتنی بر **سند جامع نیازمندی‌ها نسخه ۲.۰** — سامانه تحت‌وب BPMS با پشتیبانی کامل فارسی و راست‌به‌چپ.

## پشته فناوری (مطابق تصمیم‌های قطعی سند §۳)

| لایه | فناوری |
|------|--------|
| API | FastAPI (Python 3.12) |
| ORM / Migration | SQLAlchemy 2.x + Alembic |
| قرارداد API | Pydantic v2 |
| موتور اجرای BPMN | **SpiffWorkflow 3.2** (انتخاب‌شده پس از نمونه فنی فاز صفر) |
| فرانت‌اند | React 18 + TypeScript + Vite |
| رابط و RTL | Ant Design 5 با `direction="rtl"` + فونت وزیرمتن |
| طراح BPMN | bpmn-js 17 |
| Drag & Drop فرم | dnd-kit |
| داده پایگاه | SQLite (توسعه/پایلوت) → PostgreSQL (عملیات — فقط با تغییر `BPMS_DATABASE_URL`) |
| Worker / صف | **Celery + Redis** (عملیات) یا زمان‌بند درون‌فرایندی (توسعه — `BPMS_SCHEDULER_MODE`) |
| رویداد زنده | **SSE** با پل اختیاری Redis برای استقرار چندفرایندی |
| تست بک‌اند / رابط | pytest (۱۹۹ آزمون) / Vitest (۲۵ آزمون مشترک) |
| E2E مرورگری | **Playwright** (۱۵ آزمون — سناریوی §۳۵ کامل از UI + گزارش‌ساز) |
| آزمون بار | **Locust** — نتایج عملیاتی روی PostgreSQL: ۳٬۳۹۸ درخواست، p95 = ۴۸ms |
| یکپارچه‌سازی | **API بیرونی با idempotency + Webhook امضاشده روی صف توزیع‌شده + OIDC با PKCE/LDAP + کانکتور SOAP** (فاز ۵/۶) |
| گزارش‌سازی | **گزارش‌ساز و KPI** (شاخص‌های کلی، گلوگاه‌ها، بار کاری، حجم روزانه، گزارش ذخیره‌شده — فاز ۶) + **نمودارهای تعاملی ECharts** و **خروجی Excel/PDF فارسی** (فاز ۷) |

## اجرای سریع

```bash
# بک‌اند
cd backend
python3 -m venv .venv && source .venv/bin/activate    # اختیاری
pip install -r requirements.txt
alembic upgrade head            # ساخت جداول
python -m app.seed              # داده نمونه: کاربران، فرم‌ها، فرایند «درخواست خرید»
python -m app.seed_samples      # فاز ۸: نمونه‌پروژه‌ها (مرخصی، اصلاح تردد، مستندسازی، ماموریت، تیکت) + بانک سازمانی
uvicorn app.main:app --port 8000 --reload

# فرانت‌اند (توسعه)
cd ../frontend
npm install
npm run dev                     # http://localhost:3000 (پروکسی API به 8000)

# تولید (سرو توسط FastAPI)
npm run build                   # خروجی در frontend/dist و به‌صورت خودکار توسط بک‌اند سرو می‌شود
```

## قابلیت‌های پیاده‌سازی‌شده

### بخش اول — طراحی و اجرای فرایند
- طراح BPMN تحت‌وب با bpmn-js: باز کردن/ذخیره `.bpmn`، خروجی SVG، انتخاب عنصر و تنظیمات، **اعتبارسنجی پیش از انتشار با تفکیک خطا/هشدار** (AC-02)
- موتور اجرا SpiffWorkflow: شروع با فرم، وظیفه انسانی، دروازه انحصاری با شرط، انشعاب/اتصال موازی، زیرفرایند (Call Activity)، تایمر، فعالیت سیستمی (ServiceTask) با کانکتور، حالت خطا + **Incident قابل رسیدگی با تلاش مجدد** (AC-15)
- **بازیابی وضعیت پس از ری‌استارت** از طریق serialize/deserialize (AC-13)
- نسخه‌بندی: هر نمونه به نسخه ثابت متصل می‌ماند؛ انتشار نسخه جدید نمونه‌های جاری را تغییر نمی‌دهد (AC-14)

### بخش دوم — فرم‌ساز و داده
- سه جزء مستقل: Form Designer / Form Schema (JSON نسخه‌بندی‌شده) / Form Renderer
- انواع فیلد: متنی، عددی، مبلغ (واحد پول صریح)، تاریخ **جلالی**، **کد ملی** (رقم کنترل + حفظ صفر ابتدایی)، **موبایل** (`^09[0-9]{9}$` پس از یکسان‌سازی ارقام فارسی/عربی) (AC-04/05/06)
- اعتبارسنجی دو سطحی: مرورگر برای بازخورد سریع + **سرور به‌عنوان مرجع نهایی** با موتور مشترک قواعد
- زیرفرم تکرارشونده و تک‌نمونه‌ای با حداقل/حداکثر ردیف و اعتبارسنجی ردیف (AC-08)
- فرمول‌ساز **امن بدون eval** (Parser اختصاصی: `SUM(items.qty)`، `IF`، `ROUND`، مقایسه‌ها) — قرینه سمت مرورگر و سرور با **مجموعه آزمون مشترک**
- جداول پایه (Lookup) سلسله‌مراتبی با اتصال به کنترل‌ها و بررسی گزینه در سرور (AC-07)

### بخش سوم — قوانین، فعالیت‌ها و یکپارچه‌سازی
- شرط‌های مسیر به‌صورت عبارت محدود روی متغیرهای فرایند (`action == 'approve'`)
- **شرط‌ساز بصری روی نمودار BPMN (فاز ۴)**: ردیف‌های فیلد/عملگر/مقدار با و/یا و گروه، پیش‌نمایش عبارت، اعمال روی جریان، آزمایش روی داده نمونه، بازخوانی شرط موجود و حالت دستی برای عبارت‌های پیچیده؛ اعتبارسنجی شرط‌ها در انتشار (خطای نحو + هشدار متغیر ناشناخته)
- کانکتورهای `mock:*` و `http:METHOD:URL` با timeout و retry محدود و ثبت خطا
- محیط اسکریپت محدودشده (بدون import/open آزاد) — منع اجرای آزاد کد کاربران

### بخش چهارم — کارتابل، مشاهده و گزارش
- کارتابل: وظایف من، **صف گروهی با Claim و کنترل رقابت** (جلوگیری از دریافت هم‌زمان — AC-12)، انجام‌شده‌ها، فیلتر و جست‌وجو
- واگذاری/آزادسازی وظیفه، جانشینی در بازه زمانی
- **نمودار زنده** با نشانگر فعالیت‌های فعال/تکمیل‌شده/خطادار روی نسخه واقعی نمونه
- تاریخچه کامل رویدادها + اعلان داخل سامانه + ممیزی فقط‌مشاهده

### بخش پنجم و ششم — معماری، امنیت، کیفیت
- احراز هویت JWT + bcrypt، کنترل دسترسی نقش‌محور با مجوز صریح، محدودیت سطح API
- قالب خطای یکسان + شناسه پیگیری، OpenAPI در `/docs`
- SQLite با `foreign_keys` و WAL؛ مایگریشن Alembic با `render_as_batch` (سازگاری PostgreSQL)
- ثبت ممیزی عملیات حساس، پوشاندن داده حساس در لاگ کانکتورها

### فاز ۳ — قابلیت‌های حرفه‌ای
- **جدول تصمیم (DMN سبک)**: ورودی/خروجی/قواعد با سیاست‌های FIRST/UNIQUE/ANY/PRIORITY/COLLECT؛ ارزیاب امن بدون eval؛ اتصال به وظیفه (`decisionKey`) یا کانکتور `dmn:key`؛ اعتبارسنجی ارجاع‌ها در انتشار؛ ویرایشگر گرید + آزمون ارزیابی در UI
- **تقویم کاری**: برنامه هفتگی هفته ایرانی (شنبه تا جمعه) با وقفه‌ها، تعطیلی یک‌باره/سالانه با انتخاب جلالی؛ محاسبه مهلت وظایف بر پایه ساعات اداری (`config_json.calendarId`)؛ پیش‌نمایش مهلت
- **Worker پایدار (Celery)**: beat برای تیک تایمرها (۳۰ ثانیه) و پایش SLA (۵ دقیقه) — هشدار ۸۰٪ و فرازدگی مهلت با اعلام یک‌باره؛ حالت درون‌فرایندی برای توسعه/پایلوت بدون Redis
- **SSE**: جریان `/events/stream` به تفکیک کاربر با انتشار پس از commit؛ toast و تازه‌سازی خودکار کارتابل/نمونه/اعلان‌ها؛ پل Redis اختیاری برای چندفرایندی

### فاز ۴ — آماده‌سازی بهره‌برداری
- **شرط‌ساز بصری روی BPMN**: ساخت/بازخوانی/آزمایش شرط مسیر بدون کدنویسی + اعتبارسنجی در انتشار (پارسر امن AST سمت سرور، آینه TS سمت مرورگر)
- **Playwright E2E**: ۱۲ آزمون مرورگری شامل اجرای کامل سناریوی §۳۵ از UI (ثبت با فرم فارسی و زیرفرم، تأیید مدیر از صف گروهی، مالی، وضعیت نهایی) + آزمون شرط‌ساز روی نمودار
- **آزمون بار**: Locust با ۳ سناریو واقع‌گرایانه؛ smoke نمونه: ۱۹۸ درخواست، ۰٪ خطا، p95 = ۶۹ms (docs/load-testing.md)
- رفع اشکالات کشف‌شده در E2E: نمایش toast، محاسبه مبلغ کل فرم‌های دارای زیرفرم، نمایش وظایف Claim‌شده در کارتابل، رقابت ثبت شنونده انتخاب در طراح BPMN

### فاز ۵ — یکپارچه‌سازی
- **API بیرونی با idempotency**: `/external/v1/...` با کلید سرویس، امضای اختیاری HMAC-SHA256 + تلورانس زمانی (مقابله با بازپخش)، دامنه‌های صریح (scopes)، سقف نرخ per-client و **بازپخش پاسخ** برای درخواست تکراری (409 برای تعارض) — پنل مدیریت کلیدها/چرخش رمز
- **Webhook خروجی امضاشده**: انتشار پس از commit (هیچ webhook کاذبی برای تراکنش ناموفق)، امضای HMAC روی هر ارسال، retry و گزارش کامل تحویل‌ها
- **ورود سازمانی**: OIDC Authorization Code (کشف خودکار IdP، state امضاشده، تأمین خودکار کاربر با نقش پیش‌فرض) + LDAP bind-then-search — دکمه ورود سازمانی در صفحه ورود فقط در صورت فعال بودن
- **کانکتور SOAP 1.1**: `soap:URL|Action` با پوش از متغیرهای فرایند، escape امن، تشخیص Fault → Incident
- **آزمون بار عملیاتی روی PostgreSQL ۱۶**: ۳٬۳۹۸ درخواست در ۲ دقیقه با ۵۰ کاربر — خطای مؤثر ۰٪ (تنها 409 رقابت Claim)، p95 = ۴۸ms

### فاز ۶ — PKCE، صف توزیع‌شده Webhook و گزارش‌ساز/KPI
- **PKCE (RFC 7636) روی OIDC**: جریان Authorization Code با روش **S256** — تولید code_verifier/challenge، حمل امن verifier در state امضاشده (بدون session)، ارسال در تبادل توکن؛ **client_secret اکنون اختیاری است** (پشتیبانی کلاینت عمومی)؛ قابل خاموش‌کردن با `BPMS_OIDC_PKCE_ENABLED=false`
- **صف توزیع‌شده Webhook با Celery**: در `BPMS_SCHEDULER_MODE=celery` هر تحویل تسک مستقل `bpms.webhooks.deliver` روی صف Redis با **acks_late و backoff نمایی (۱۰s تا ۳۰۰s)** و سقف ۵ تلاش؛ تسک beat `bpms.webhooks.sweep` هر ۵ دقیقه تحویل‌های یتیم (سقوط Worker) را بازیابی/رد می‌کند؛ fallback خودکار به نخ پس‌زمینه در توسعه/قطعی Broker
- **گزارش‌ساز و KPI**: صفحه «گزارش‌ساز و KPI» با شاخص‌های کلی (نرخ تکمیل، میانگین/صدک ۵۰ و ۹۵ زمان چرخه، انتظار/رسیدگی وظایف، نرخ نقض SLA)، **گلوگاه‌ها به تفکیک گام فرایند**، **بار کاری افراد و صف‌های گروهی**، حجم روزانه (نمودار) و **گزارش‌های ذخیره‌شده** با اجرای دوباره — مجوزهای `report.view` / `report.manage` + لاگ ممیزی

### فاز ۷ — نمودارهای تعاملی، خروجی Excel/PDF و آزمون E2E گزارش‌ساز
- **نمودارهای تعاملی ECharts**: حجم روزانه (میله + خط هموار با **zoom اسلایدر/درون‌نمودار**)، دونات ترکیب وضعیت با مجموع در مرکز، گلوگاه‌ها (میله افقی دوتایی با گرادیان) و بار کاری (میله انباشته) — برچسب جلالی، اعداد فارسی، tooltip خوانا و واکنش‌گرا به فیلترها
- **خروجی Excel (xlsx)**: کتاب‌کار چندبرگی openpyxl (راهنما، شاخص‌های کلی، گلوگاه‌ها، بار کاری، حجم روزانه) با برگه‌های راست‌به‌چپ، سرستون بولد، تاریخ جلالی و مدت خوانا — `GET /reports/export/excel`
- **خروجی PDF فارسی (RTL)**: reportlab با قلم **Vazirmatn** (همراه مخزن)، اشکال نمایش + python-bidi برای متن صحیح، جداول معکوس‌ستون، پانویس صفحه‌بندی — `GET /reports/export/pdf`
- **خروجی گزارش ذخیره‌شده**: `GET /reports/saved/{id}/export?format=excel|pdf` + دکمه‌های خروجی در نوار بالا و جدول گزارش‌های ذخیره‌شده؛ ثبت `report.exported` در لاگ ممیزی
- **آزمون E2E گزارش‌ساز**: ۳ آزمون Playwright (رندر نمودارها با داده واقعی تولیدشده از UI، تغییر فیلتر و برگه‌ها، ذخیره/اجرا/حذف گزارش، دانلود Excel/PDF با بررسی امضای بایت) — مجموع E2E: ۱۵ آزمون

### فاز ۸ — درگ‌اند‌دراپ کامل، تم فرم‌ها، پالت کامل BPMN و بانک سازمانی
- **درگ‌اند‌دراپ واقعی در فرم‌ساز**: کشیدن جزء از پالت و رهاکردن روی بوم (dnd-kit) با پیش‌نمایش شناور، نشانگر محل درج، هایلایت بوم + جابه‌جایی فیلدهای بوم با درگ + کلیک برای افزودن (هر دو)
- **تم و ظاهر فرم‌ها**: ۷ پیش‌تنم آماده (فیروزه‌ای، نیلی، سبز، آبی، سرخابی، تیره، مینیمال) + انتخاب رنگ اصلی/سرصفحه/برچسب/پس‌زمینه، گردی گوشه و چیدمان فشرده — تم در schema ذخیره و در همه نمایش‌دهنده‌ها (پیش‌نمایش/شروع/وظیفه) با ConfigProvider اعمال می‌شود
- **پالت کامل BPMN**: ۷۱ عنصر استاندارد — همه رویدادهای شروع/میانی/پایان/مرزی با تعریف‌های پیام/زمان/سیگنال/شرط/خطا/تشدید/جبران/لغو/پیوند، وظایف کاربر/سرویس/اسکریپت/ارسال/دریافت/دستی/قواعد، فراخوانی و زیرفرایند (باز/جمع/تراکنش/رویدادی)، ۵ دروازه، داده و مخزن، گروه و حاشیه‌نویسی، استخر — با آیکون‌های رسمی bpmn-font و درگ‌اند‌دراپ بومی
- **رنگ‌آمیزی عناصر نمودار**: ۸ جفت‌رنگ سازمانی + رنگ سفارشی + پاک‌کردن — ذخیره در BPMN (bioc) و ماندگار در نسخه
- **بانک سازمانی**: صفحه «بانک سازمانی» با سه برگه — فیلدهای سازمانی (فیلدهای استاندارد سازمان که در پالت فرم‌ساز کنار اجزای پایه ظاهر می‌شوند)، بانک فرم‌ها و بانک فرایندها (ذخیره الگو از فرم/فرایند موجود + ساخت یک‌کلیکی فرم/فرایند جدید از الگو با حفظ اتصالات)
- **نمونه‌پروژه‌های صفر تا صد**: `python -m app.seed_samples` — مرخصی کارکنان (با ارجاع شرطی به منابع انسانی برای بیش از ۳ روز)، اصلاح تردد، مستندسازی اسناد (بازبینی/تأیید/بایگانی)، ماموریت اداری (سقف هزینه + تأیید مالی + صدور حکم) و تیکت پشتیبانی IT (حلقه حل و تأیید درخواهنده) — هر کدام با فرم تم‌دار، BPMN با DI کامل، مسئول/نتیجه/مهلت و انتشار خودکار + نقش‌های hr/it_support و کاربران hr1/it1 + ثبت الگوها در بانک سازمانی
- **رفع اشکال**: «خطای ناشناخته» هنگام ایجاد نسخه جدید فرایند بدون نسخه (دکمه فقط با وجود نسخه + ساخت «نسخه اول» از فایل بارگذاری‌شده)، نمایش پیام خطای واقعی سرور به‌جای پیام عمومی، باز شدن فرم‌ساز بدون پارامتر `?v=` (انتخاب خودکار آخرین نسخه)، افزودن CSS رسمی bpmn-js (ظاهر پالت/کانتکست‌پد) و پشتیبانی ذخیره `theme` در API فرم‌ها

## سناریوی نمونه سند §۳۵ (درخواست خرید)

با داده اولیه آماده است: ثبت درخواست (فرم با کد ملی/موبایل/تاریخ شمسی/اقلام) → تأیید مدیر (صف گروهی نقش مدیر) → انشعاب موازی (سرویس ثبت سفارش + اطلاع‌رسانی مالی) → خاتمه. مسیرهای «رد» و «بازگشت برای اصلاح» نیز فعال‌اند.

آزمون خودکار همین سناریو از طریق HTTP: `python3 scripts/e2e_api_test.py` (سرور باید روشن باشد).

آزمون مرورگری کامل همین سناریو از رابط کاربری: `cd frontend && npm run e2e` (Playwright — سرور و دیتابیس یکبارمصرف خودکار بالا می‌آید).

  load/              # فاز ۴/۵: locustfile.py + نتایج نمونه SQLite و عملیاتی PostgreSQL

# محدودیت‌های نسخه جاری و قابلیت‌های خارج از تحویل

مطابق اصل سند (§۶، §۳۶) — فهرست صریح محدودیت‌ها برای جلوگیری از ادعای «پشتیبانی کامل BPMN»:

## اجرای BPMN

- عناصر Message/Signal/Error/Escalation/Compensation Boundary Event، Send/Receive Task، Loop و Multi-Instance، Transaction Subprocess، Complex/Event-Based Gateway: **قابل طراحی ولی بدون پشتیبانی اجرایی** (انتشار مسدود یا بدون تضمین رفتار — ماتریس bpmn-coverage.md).
- Conversation و Choreography پیاده‌سازی نشده‌اند.
- شرط مسیر با معنای پایتونی ارزیابی می‌شود؛ DMN/جدول تصمیم و شرط‌ساز بصری در فاز ۳ است.
- تایمرهای Date/Cycle تست اختصاصی ندارند؛ فقط Duration آزمون شده است.

## فرم و قوانین

- اعتبارسنجی یکتایی فیلد «در محدوده تعریف‌شده» پیاده نشده است.
- وابستگی والد/فرزند جداول پایه (مانند استان→شهر) از طریق ساختار درختی پشتیبانی می‌شود اما فیلتر خودکار Cascading در Renderer فاز بعدی است.
- قواعد بین فرم اصلی و زیرفرم فقط از طریق فرمول‌های تجمیعی (SUM/MIN/MAX/COUNT) پشتیبانی می‌شود.
- اجرای موقت (Draft) الزامی‌ها را می‌پذیرد اما هنوز دکمه/جریان اختصاصی در UI ندارد.

## زیرساخت

- زمان‌بند تایمرها «سبک» است (فراخوانی tick در تعاملات و endpoint)؛ Worker پایدار (Celery/صف) و SSE/WebSocket فاز عملیاتی است (سند §۲۱/§۲۸).
- ارائه API بیرونی با کلید/امضای Webhook و idempotency key اختصاصی هنوز کامل نشده (الگوی idempotency در تکمیل وظیفه برقرار است).
- پیامک/ایمیل اعلان متصل نشده (فقط اعلان درون‌سامانه).
- SOAP و احراز هویت OIDC/LDAP فاز ۳ است.
- گزارش‌ساز عمومی، KPI میانگین زمان رسیدگی و گلوگاه‌ها فاز جداگانه است.
- کنترل هم‌زمانی روی PostgreSQL با SELECT FOR UPDATE به‌صورت صریح افزوده نشود، اتکا به تراکنش استاندارد است (نقطه توسعه مستند در architecture.md).

## تست

- Playwright E2E مرورگری هنوز افزوده نشده (سناریوی §۳۵ با HTTP + پیمایش دستی مرورگر پوشش داده شد)؛ افزودن آن در فاز ۴ طبق سند §۳۲.
